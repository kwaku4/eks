# Observability details

## What's already wired up by Terraform

- **EKS control-plane logs → CloudWatch**: `enabled_cluster_log_types` in
  `terraform/modules/eks/main.tf` turns on `api`, `audit`, `authenticator`,
  `controllerManager`, and `scheduler` logs, shipped to the log group created
  in the same module (`aws_cloudwatch_log_group.eks`).
- **`amazon-cloudwatch-observability` EKS add-on**: installs the CloudWatch
  agent + Fluent Bit as DaemonSets automatically, giving you container logs
  and Container Insights dashboards (CPU/memory/network per pod and node)
  with zero extra Helm charts. The node IAM role already has
  `CloudWatchAgentServerPolicy` attached so this add-on can push metrics.
- **`metrics-server` EKS add-on**: enables `kubectl top nodes` / `kubectl top
  pods` and is a prerequisite for any HorizontalPodAutoscaler.
- **RDS logs**: `enabled_cloudwatch_logs_exports = ["postgresql", "upgrade"]`
  ships Postgres logs to CloudWatch; the parameter group also sets
  `log_min_duration_statement = 1000` to flag slow queries.
- **Alarms → SNS**: three CloudWatch alarms (`rds_free_storage`,
  `rds_high_cpu`, `rds_connection_saturation`) in `terraform/main.tf` publish
  to an SNS topic. Set `alert_email` in your `terraform.tfvars` to get an
  email subscription created automatically, or subscribe a Slack webhook /
  PagerDuty integration to the topic ARN after apply.
- **App-level health checks**: `/health` in `app/app.py` does a real `SELECT
  1` against Postgres, not just "the process is up" — so probe failures are
  meaningful. `k8s/deployment.yaml` wires this into `readinessProbe` and
  `livenessProbe`.

## Wiring the app to RDS (secret handling)

The RDS master password is generated by Terraform (`random_password`) and
stored only in AWS Secrets Manager — never in state outputs printed to a
terminal transcript, never in a committed file. To deploy the app:

```bash
cd terraform
terraform output -raw rds_endpoint          # -> use in k8s/configmap.yaml DB_HOST
terraform output -raw rds_secret_arn        # -> use below

SECRET_JSON=$(aws secretsmanager get-secret-value \
  --secret-id "$(terraform output -raw rds_secret_arn)" \
  --query SecretString --output text)

kubectl create secret generic demo-app-db-credentials \
  --namespace demo \
  --from-literal=DB_USER=$(echo "$SECRET_JSON" | jq -r .username) \
  --from-literal=DB_PASSWORD=$(echo "$SECRET_JSON" | jq -r .password) \
  --dry-run=client -o yaml | kubectl apply -f -
```

`k8s/secret-example.yaml` documents this same flow inline and is a template
only — it is never meant to be filled in with real values and committed.

## What I'd add with more time

- **kube-prometheus-stack** (Helm) for PromQL-based alerting and richer
  Grafana dashboards than CloudWatch's default views.
- **OpenTelemetry** auto-instrumentation on the Flask app for distributed
  tracing, especially useful once there's more than one service.
- **Synthetic checks**: a scheduled Lambda or CloudWatch Synthetics canary
  hitting the public LB endpoint's `/health`, independent of in-cluster
  probes, to catch LB/DNS-level failures the cluster itself can't see.
- **SLOs**: define an availability/latency SLO for the demo endpoint and
  back it with a CloudWatch composite alarm or Prometheus recording rules.
